Rewrite the expenses tab parent screen to use the new presentational components, following the Phase 7 home screen centralized data fetching pattern from `app/(app)/(tabs)/index.tsx`.

**Data fetching (preserve and adapt from existing code):**
- Keep the existing `fetchData` pattern using `Promise.all` for balances + expenses + settlements.
- Keep `useFocusEffect` for refetch on screen focus.
- Keep `onRefresh` for pull-to-refresh with `RefreshControl`.
- Adapt `getDateLabel()` to return exactly three groups: 'TODAY', 'YESTERDAY', 'EARLIER' (uppercase). The old function returned formatted dates for older entries -- now all dates before yesterday go into 'EARLIER'.
- Keep `formatCurrency` using `Intl.NumberFormat`.
- Keep the profile fetching logic (fetch profiles for balance users and history users).
- Remove `AVATAR_COLORS` and `getInitials` -- replaced by Avatar component in child components.
- Remove `getRecentExpenseForUser` and `handleVenmoRequest` -- replaced by Remind (Share sheet) and simplified Settle navigation.

**New features:**

1. **Inline expand for expense splits:**
   - State: `expandedId: string | null` and `splitsCache: Record<string, SplitWithProfile[]>`.
   - `handleExpensePress(expenseId)`: toggle expandedId. If expanding and splits not cached, fetch from `expense_splits` table filtered by expense_id, then fetch profiles for split user_ids, combine into `SplitWithProfile[]` and cache.
   - Clear `splitsCache` on `fetchData` (pull-to-refresh or focus refetch) to avoid stale data (Research Pitfall 2).

2. **Remind via Share sheet:**
   - Import `{ Share }` from 'react-native'.
   - `handleRemind(memberName: string, amount: number)`: call `Share.share({ message: "Hey {memberName}, you owe ${amount} on RoomY. Can you settle up?" })`. Wrap in try/catch (user may cancel).

3. **Settle navigation:**
   - `handleSettle(userId: string, amount: number)`: navigate to `/(app)/expenses/settle?userId={userId}&amount={amount}&direction=you_owe` using `router.push`. This is for members YOU OWE -- you settle up with them.

4. **Member press navigation:**
   - `handleMemberPress(userId: string)`: navigate to `/(app)/expenses/member-history?userId={userId}` using `router.push`. This triggers on row tap (not button tap).

5. **Pagination:**
   - Use batch size of 20. Track `offset` and `hasMore` state.
   - Initial fetch loads first 20 from each table (expenses + settlements).
   - `loadMore()`: triggered when user scrolls near bottom. Use `onScroll` handler to detect `contentOffset.y + layoutHeight >= contentSize.height - 200`. Fetch next batch, merge into existing grouped history maintaining sort order and date groups.
   - Merge logic: append new items to historyItems, re-sort, re-group. The 'EARLIER' group accumulates.
   - Show a small ActivityIndicator at the bottom of the list when loading more.

**Screen composition:**
```
<ScrollView refreshControl={...} onScroll={handleScroll}>
  <BalanceSection
    balances={filteredBalances}
    currentUserId={user?.id}
    onSettle={handleSettle}
    onRemind={handleRemind}
    onMemberPress={handleMemberPress}
  />
  {groupedHistory.length === 0 ? (
    <EmptyState onAddExpense={() => router.push('/(app)/expenses/add')} />
  ) : (
    <HistorySection
      groups={groupedHistory}
      expandedId={expandedId}
      splitsCache={splitsCache}
      onExpensePress={handleExpensePress}
      currentUserId={user?.id}
    />
  )}
  {loadingMore && <ActivityIndicator />}
</ScrollView>
```

- Padding: `contentContainerStyle={{ paddingHorizontal: 20, paddingTop: 16, paddingBottom: 96 }}` (px-5 = 20px, consistent with home screen).
- Loading state: centered ActivityIndicator with brand color (same pattern as current).
- Background: bg-neutral-bg on outer View.

**Do NOT:**

- Add edit/delete to expanded rows (deferred).
- Use FlatList for history (ScrollView is required since balance section and history scroll as one unit -- Research anti-pattern).
- Navigate to [id].tsx on expense tap (changed to inline expand per user decision).

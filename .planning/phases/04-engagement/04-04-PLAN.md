  <name>Task 2: Guard push token registration against missing projectId</name>
  <files>lib/notifications.ts</files>
  <action>
In `lib/notifications.ts`, the current code (lines 42-48) resolves projectId and passes it directly to `getExpoPushTokenAsync`, which throws when projectId is undefined (no EAS config in app.json, common in Expo Go):

```typescript
const projectId =
  Constants?.expoConfig?.extra?.eas?.projectId ??
  Constants?.easConfig?.projectId;

const tokenData = await Notifications.getExpoPushTokenAsync({
  projectId,
});
```

Fix by adding a guard before the `getExpoPushTokenAsync` call:

1. After the `projectId` resolution, add:
   ```typescript
   if (!projectId) {
     console.log(
       "Push notifications: no EAS projectId found. " +
       "Push token registration requires an EAS-configured build. " +
       "Skipping registration."
     );
     return null;
   }
   ```

2. This ensures the function returns null gracefully (same as the Device.isDevice and permission-denied guards above it) rather than throwing an unhandled error.

3. Wrap the entire `getExpoPushTokenAsync` + supabase update block in a try/catch as a safety net:
   ```typescript
   try {
     const tokenData = await Notifications.getExpoPushTokenAsync({
       projectId,
     });
     const token = tokenData.data;

     const { error } = await supabase
       .from("profiles")
       .update({ expo_push_token: token })
       .eq("id", userId);

     if (error) {
       console.error("Failed to store push token:", error.message);
     } else {
       console.log("Push token registered:", token);
     }

     return token;
   } catch (err) {
     console.error("Push token registration failed:", err);
     return null;
   }
   ```

4. Do NOT modify `setupNotificationChannels` or any other function. Only change the `registerForPushNotifications` function.

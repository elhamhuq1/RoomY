**Edge Function 1: `supabase/functions/push-expense/index.ts`**

This function is triggered by a Database Webhook on INSERT to the expenses table.

Implementation:
1. Parse incoming webhook payload to get the new expense record
2. Create Supabase client with `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (service role bypasses RLS)
3. Query household_members for the expense's household_id, excluding the expense creator (created_by)
4. Query profiles for those user_ids to get expo_push_token and display_name
5. Query notification_preferences for those user_ids to check expenses_enabled
6. Filter to users who: have a non-null expo_push_token AND have expenses_enabled !== false (default true if no preference row exists)
7. Get creator's display_name from profiles
8. Format notification: title = "New Expense", body = "{creatorName} added ${amount} for {description}" (per user decision)
9. POST to `https://exp.host/--/api/v2/push/send` with array of notification objects:
   - `to`: push token
   - `title`: "New Expense"
   - `body`: formatted message
   - `sound`: "default"
   - `data`: `{ type: 'expense', expenseId: record.id }`
   - `channelId`: "expenses" (for Android channel routing)
10. Return response

Use Deno imports:
```typescript
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';
```

Handle errors gracefully -- log and return 200 even on partial failure (don't block the webhook).

NOTE on grouping: Per research recommendation, implement individual notifications for v1. The user's grouping request ("Sarah added 3 expenses ($127.00 total)") adds significant complexity (pending queue, aggregation timer) that is rarely triggered in 2-4 person households. Individual notifications are informative and functional. Add grouping in v2 if needed.

**Edge Function 2: `supabase/functions/push-chore-reminder/index.ts`**

This function is invoked by a cron schedule (daily). Per user decision, chore reminders fire on the morning of the due date.

Implementation:
1. Create Supabase client with service role key
2. Get today's date range (start of day to end of day in UTC -- for v1, use UTC; timezone handling noted as open question in research)
3. Query chores where:
   - `is_active = true`
   - `next_due_at` is between today start and today end (chores due today)
4. For each chore found:
   a. Get current_assignee user_id
   b. Query profiles for that user_id to get expo_push_token
   c. Query notification_preferences for that user_id to check chores_enabled
   d. If token exists AND chores_enabled !== false:
      - Send push: title = "Chore Reminder", body = "{choreName} is due today", data = { type: 'chore', choreId: chore.id }, channelId = "chores"
5. Batch all notifications and POST to Expo Push API in one request
6. Return summary response

For the cron trigger: document that this Edge Function should be invoked via Supabase Dashboard > Edge Functions > Schedule (cron expression: `0 13 * * *` for 8 AM EST / 1 PM UTC). The cron setup is a dashboard configuration step.

Both Edge Functions must:
- Use `Deno.serve(async (req) => { ... })` pattern
- Handle missing env vars gracefully
- Return proper Response objects
- Log errors to console for debugging

Create `supabase/migrations/00004_chores.sql` following the established pattern from 00003_groceries.sql:

**Tables:**

1. `chores` table:
   - id UUID PK, household_id UUID FK households ON DELETE CASCADE NOT NULL, name TEXT NOT NULL, frequency TEXT NOT NULL CHECK (frequency IN ('daily', 'weekly', 'monthly', 'custom')), custom_interval_days INT (nullable, used only when frequency='custom'), rotation_order UUID[] NOT NULL DEFAULT '{}', current_assignee_index INT NOT NULL DEFAULT 0, current_assignee UUID REFERENCES auth.users, next_due_at TIMESTAMPTZ NOT NULL, last_completed_at TIMESTAMPTZ, created_by UUID REFERENCES auth.users NOT NULL, created_at TIMESTAMPTZ DEFAULT now(), is_active BOOLEAN DEFAULT true

2. `chore_completions` table:
   - id UUID PK, chore_id UUID FK chores ON DELETE CASCADE NOT NULL, completed_by UUID REFERENCES auth.users NOT NULL, completed_at TIMESTAMPTZ DEFAULT now(), is_disputed BOOLEAN DEFAULT false, disputed_by UUID REFERENCES auth.users, disputed_at TIMESTAMPTZ, is_reverted BOOLEAN DEFAULT false, reverted_at TIMESTAMPTZ

3. `chore_swap_requests` table:
   - id UUID PK, chore_id UUID FK chores ON DELETE CASCADE NOT NULL, requested_by UUID REFERENCES auth.users NOT NULL, requested_to UUID REFERENCES auth.users NOT NULL, status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'accepted', 'declined')), created_at TIMESTAMPTZ DEFAULT now(), resolved_at TIMESTAMPTZ

**Indexes:**
- idx_chores_household ON chores(household_id) WHERE is_active = true
- idx_chore_completions_chore ON chore_completions(chore_id)
- idx_chore_completions_user ON chore_completions(completed_by)
- idx_chore_swap_requests_pending ON chore_swap_requests(chore_id) WHERE status = 'pending'

**RLS policies (use get_user_household_ids() -- NEVER self-referencing subqueries):**
- All three tables: Enable RLS. SELECT, INSERT, UPDATE, DELETE policies for household members. Pattern: `household_id IN (SELECT get_user_household_ids())` for chores and via join to chores for completions and swap_requests.
- For chore_completions: SELECT/INSERT allowed for household members (join through chores.household_id). No direct household_id column -- use `chore_id IN (SELECT id FROM chores WHERE household_id IN (SELECT get_user_household_ids()))`.
- Same pattern for chore_swap_requests.

**Functions:**

1. `complete_chore(p_chore_id UUID, p_completed_by UUID)` RETURNS JSON -- SECURITY DEFINER, SET search_path = '':
   - Validates chore exists and is_active
   - Inserts into chore_completions
   - Advances rotation: next_index = (current_assignee_index + 1) % array_length(rotation_order, 1), next_assignee = rotation_order[next_index + 1] (Postgres 1-indexed arrays!)
   - Computes next_due_at based on frequency (daily +1d, weekly +7d, monthly +1mo, custom +custom_interval_days days)
   - Updates chores SET current_assignee_index, current_assignee, next_due_at, last_completed_at
   - Returns JSON with completion_id, next_assignee, next_due_at

2. `claim_chore(p_chore_id UUID, p_claimed_by UUID)` RETURNS void -- SECURITY DEFINER, SET search_path = '':
   - Updates chores SET current_assignee = p_claimed_by
   - Also updates current_assignee_index to match p_claimed_by's position in rotation_order (find index with array_position)
   - If p_claimed_by not in rotation_order, raise exception

3. `dispute_completion(p_completion_id UUID, p_disputed_by UUID)` RETURNS void -- SECURITY DEFINER, SET search_path = '':
   - Updates chore_completions SET is_disputed = true, disputed_by = p_disputed_by, disputed_at = now()
   - Only if is_reverted = false (can't dispute already-reverted)

4. `resolve_swap_request(p_request_id UUID, p_status TEXT)` RETURNS void -- SECURITY DEFINER, SET search_path = '':
   - Updates chore_swap_requests SET status = p_status, resolved_at = now()
   - If accepted: update chores SET current_assignee to the requester, adjust current_assignee_index via array_position

5. `auto_revert_stale_disputes()` RETURNS void -- SECURITY DEFINER, SET search_path = '':
   - UPDATE chore_completions SET is_reverted = true, reverted_at = now() WHERE is_disputed = true AND is_reverted = false AND disputed_at < now() - interval '24 hours'

**pg_cron schedule:**
- `SELECT cron.schedule('revert-stale-disputes', '0 * * * *', 'SELECT public.auto_revert_stale_disputes()')` -- runs hourly
- Wrap in a DO block with exception handling in case pg_cron is not enabled: try cron.schedule, if it fails log a NOTICE that pg_cron is not available and disputes will be checked client-side

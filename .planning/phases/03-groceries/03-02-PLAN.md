**Create app/(app)/groceries/complete-trip.tsx:**

This screen is navigated to from the "Complete Trip" button on the grocery list. It collects the receipt total, who paid, and who to split between, then calls the `complete_grocery_trip` RPC to atomically archive items and create the expense.

**Layout and fields (reuse patterns from expenses/add.tsx):**

1. **Receipt total input:**
   - Label: "Receipt Total"
   - Same $ + TextInput pattern as expenses/add.tsx amount field
   - `keyboardType="decimal-pad"`, same `handleAmountChange` validation (digits + one decimal, max 2 places)
   - Auto-focus on mount

2. **Payer picker:**
   - Label: "Paid by"
   - Horizontal scrollable avatar chips -- exact same pattern as expenses/add.tsx payer section
   - Default to current user
   - Use the same AVATAR_COLORS, getInitials, avatar styling from add.tsx. Extract these to a shared location OR duplicate them (they're small utility functions). Duplicating is acceptable to avoid scope creep.

3. **Member picker (split between):**
   - Label: "Split between"
   - Vertical list with checkboxes -- exact same pattern as expenses/add.tsx split section
   - Default: all household members selected
   - Show per-person share amount when valid amount entered (equal split calculation)
   - Don't allow deselecting last member

4. **Summary section:**
   - Show: "{N} items checked off" (count from grocery list)
   - Show the per-person split amount

5. **Submit button:**
   - "Complete Trip" button, primary color, disabled state when invalid
   - ActivityIndicator while submitting

**On submit:**
- Call `supabase.rpc('complete_grocery_trip', { p_household_id, p_total_amount, p_paid_by, p_split_user_ids, p_created_by })`
- On success: `router.back()` to return to grocery list (which will auto-update via realtime as items are archived/deleted)
- On error: show error message in red banner (same pattern as add.tsx)

**Fetching members:**
- Same `fetchMembers` pattern as expenses/add.tsx: query household_members, then query profiles separately, combine client-side
- Set current user as default payer, all members as default split

**Create app/(app)/groceries/trip-history.tsx:**

A simple archive view showing past completed shopping trips for the household.

**Data fetching:**
- Query: `supabase.from('grocery_trips').select('*').eq('household_id', household.id).order('completed_at', { ascending: false })`
- For each trip, also fetch its archived items: `supabase.from('grocery_items').select('*').eq('trip_id', trip.id).order('name')`
- Alternatively, fetch all items for all displayed trips in a single query using `.in('trip_id', tripIds)` and group client-side for efficiency

**Display:**
- Screen title: "Trip History" (set via expo-router Stack.Screen options or navigation header)
- List of trip cards, each showing:
  - Date (formatted: "Mar 11, 2026" or relative like "Today", "Yesterday")
  - Total amount (formatted as currency)
  - Item count: "{N} items"
  - Expandable or always-visible item list showing archived item names and quantities
- If no trips: empty state with "No completed trips yet" message

**Styling:**
- White card backgrounds with rounded-xl, shadow-sm
- Follow the same visual language as the expenses history list
- Use ScrollView with `style={{ flex: 1 }}` per project convention
- Standard bg-surface-50 background

**Navigation:**
- This screen is pushed from the grocery list (not a tab), so it appears in the stack with a back button automatically via expo-router

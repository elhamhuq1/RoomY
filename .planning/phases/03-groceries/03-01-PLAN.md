**Migration file (00003_groceries.sql):**

Create two tables following the exact patterns from 00002_expenses.sql:

1. `grocery_trips` table (must be created FIRST because grocery_items references it):
   - id UUID PK, household_id UUID FK households ON DELETE CASCADE NOT NULL, total_amount NUMERIC(10,2) NOT NULL CHECK > 0, expense_id UUID FK expenses ON DELETE SET NULL, paid_by UUID FK auth.users NOT NULL, created_by UUID FK auth.users NOT NULL, completed_at TIMESTAMPTZ DEFAULT now()

2. `grocery_items` table:
   - id UUID PK, household_id UUID FK households ON DELETE CASCADE NOT NULL, name TEXT NOT NULL, quantity INT DEFAULT 1 CHECK > 0, is_checked BOOLEAN DEFAULT false, trip_id UUID FK grocery_trips ON DELETE SET NULL, archived_at TIMESTAMPTZ, created_by UUID FK auth.users NOT NULL, created_at TIMESTAMPTZ DEFAULT now()

3. Indexes:
   - Partial index on grocery_items(household_id) WHERE trip_id IS NULL (active items only)
   - Index on grocery_items(trip_id)
   - Index on grocery_trips(household_id)

4. Realtime setup (CRITICAL -- without these, real-time won't work):
   - `ALTER TABLE grocery_items REPLICA IDENTITY FULL;` (required for non-PK column filtering on UPDATE events)
   - `ALTER PUBLICATION supabase_realtime ADD TABLE grocery_items;`

5. RLS policies on both tables using `household_id IN (SELECT public.get_user_household_ids())` pattern (matching expenses):
   - grocery_items: SELECT, INSERT (with created_by = auth.uid()), UPDATE, DELETE -- all for household members
   - grocery_trips: SELECT, INSERT (with created_by = auth.uid()) -- household members can view and create

6. `complete_grocery_trip` RPC function (SECURITY DEFINER, SET search_path = ''):
   - Parameters: p_household_id UUID, p_total_amount NUMERIC, p_paid_by UUID, p_split_user_ids UUID[], p_created_by UUID
   - Returns JSON with trip_id and expense_id
   - Steps in order: (a) INSERT grocery_trips, (b) UPDATE grocery_items SET trip_id, archived_at for checked items, (c) DELETE unchecked items with no trip_id, (d) INSERT expense, (e) calculate equal splits with penny-accurate rounding (ROUND(amount / array_length, 2)), (f) INSERT expense_splits for each user
   - Use the exact SQL pattern from 03-RESEARCH.md Pattern 3

Apply this migration to the live Supabase database using the Supabase MCP `apply_migration` tool (migration name: "groceries"). If the MCP tool is not available, save the SQL file and note that the user must apply it manually via the Supabase dashboard.

**Replace groceries.tsx placeholder** with the full grocery list screen:

**State management:**
- `items: GroceryItem[]` -- all active (non-archived) items for the household
- `newItemName: string` -- text input for adding items
- `editingItem: { id: string, name: string, quantity: number } | null` -- currently editing item (modal or inline)
- `loading: boolean` -- initial fetch loading state

**Data fetching (on mount):**
- Fetch active grocery items: `supabase.from('grocery_items').select('*').eq('household_id', household.id).is('trip_id', null).order('created_at', { ascending: false })`
- Use `useSession()` hook for user, household

**Realtime subscription (useEffect with household.id dependency):**
- Channel name: `grocery-${household.id}`
- Subscribe to `postgres_changes` on `grocery_items` table with filter `household_id=eq.${household.id}`
- Handle all three event types:
  - INSERT: Add to state if not already present (deduplicate by ID to prevent double-add from optimistic + realtime). Only add if `trip_id` is null (not archived).
  - UPDATE: Replace existing item in state by ID (idempotent)
  - DELETE: Remove from state by `payload.old.id`
- Cleanup: `supabase.removeChannel(channel)` in useEffect return

**Add item (with optimistic insert):**
- Text input at top of screen with add button (Ionicons "add-circle")
- On submit: generate temp UUID, create optimistic GroceryItem with quantity 1, prepend to items state, then INSERT to supabase. On error, remove optimistic item. On success, replace temp ID with real data (realtime will also fire but dedup handles it).
- Clear input after add. Dismiss keyboard.

**Check/uncheck item (with optimistic toggle):**
- Checkbox (Ionicons "checkbox" / "square-outline") on each row
- Optimistic: toggle `is_checked` in local state immediately
- Server: `supabase.from('grocery_items').update({ is_checked: !item.is_checked }).eq('id', item.id)`
- On error: revert local state

**Two-section list display (per user decision: flat list, newest at top):**
- Split items into `uncheckedItems` (active, top) and `checkedItems` (completed, bottom)
- Both sorted by created_at descending (newest first)
- Use ScrollView (NOT FlatList -- per research anti-patterns, grocery lists are small)
- Checked items section has a "Completed" label header and items rendered with gray/muted styling (opacity-50 or text-gray-400)

**Swipe-to-delete:**
- Import `ReanimatedSwipeable` from `react-native-gesture-handler/ReanimatedSwipeable`
- Each item row wrapped in ReanimatedSwipeable
- Right action: red background with trash icon (Ionicons "trash")
- On swipe open: delete item -- optimistic remove from state, then `supabase.from('grocery_items').delete().eq('id', item.id)`. On error, re-add to state.
- `rightThreshold={80}`

**Tap to edit item:**
- On item tap, show an edit modal (React Native Modal) or inline editing:
  - Name text input (pre-filled)
  - Quantity stepper: minus button / number / plus button (min 1, per user decision)
  - Save and Cancel buttons
- On save: optimistic update name and quantity in local state, then `supabase.from('grocery_items').update({ name, quantity }).eq('id', item.id)`. Revert on error.

**Quantity stepper on each item row (always visible):**
- Show quantity badge/stepper on each unchecked item row: [-] {qty} [+]
- Per user decision: "Each item has a name and a quantity (separate +/- stepper field)"
- Tapping +/- updates quantity optimistically and syncs to server

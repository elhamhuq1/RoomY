Fix two issues in groceries.tsx:

**Swipe-to-delete (primary fix):**
1. In the `RightSwipeAction` component (currently lines ~66-72):
   - Accept `onDelete` callback prop: `function RightSwipeAction({ onDelete }: { onDelete: () => void })`
   - Wrap the content in a `Pressable` with `onPress={onDelete}` so users can TAP to delete
   - Set a fixed width (w-20 or 80px) for consistent swipe reveal size
   - Add a "Delete" Text label below the trash icon (white, text-xs, font-medium)

2. In `renderItemRow` (currently lines ~370-430), on the `ReanimatedSwipeable`:
   - REMOVE the `onSwipeableOpen` callback entirely (this is what causes auto-delete)
   - Keep `renderRightActions` but pass a closure: `renderRightActions={() => <RightSwipeAction onDelete={() => deleteItem(item.id)} />}`
   - Add `overshootRight={false}` to prevent the row from overshooting past the action panel
   - Keep `rightThreshold={80}` as-is (it controls snap-open, which is fine when it doesn't auto-delete)

3. Store a ref for each swipeable to close it after delete:
   - Add `const swipeableRefs = useRef<Record<string, any>>({})` to the component
   - In `renderItemRow`, add a `ref` callback: `ref={(ref) => { if (ref) swipeableRefs.current[item.id] = ref; }}`
   - In the `deleteItem` function, before removing from state, call `swipeableRefs.current[itemId]?.close()` and `delete swipeableRefs.current[itemId]`

Fix two issues in groceries.tsx:

**Modal keyboard avoidance:**
1. Inside the `<Modal>` (currently lines ~564-650), wrap the modal content (the inner Pressable card, NOT the backdrop Pressable) with a `KeyboardAvoidingView`:
   ```jsx
   <Modal visible={editingItem !== null} transparent animationType="fade" onRequestClose={() => setEditingItem(null)}>
     <KeyboardAvoidingView
       behavior={Platform.OS === "ios" ? "padding" : "height"}
       style={{ flex: 1 }}
     >
       <Pressable
         className="flex-1 items-center justify-center bg-black/40"
         onPress={() => setEditingItem(null)}
       >
         <Pressable className="mx-8 w-full max-w-sm rounded-2xl bg-white p-6" onPress={() => {}}>
           {/* ... existing modal content unchanged ... */}
         </Pressable>
       </Pressable>
     </KeyboardAvoidingView>
   </Modal>
   ```
   The KeyboardAvoidingView must be the FIRST child of Modal (before the backdrop Pressable). This is critical because Modal renders in a separate native view hierarchy -- the screen-level KAV has no effect on Modal content. Do NOT remove the outer screen-level KeyboardAvoidingView (it still helps the add-item input).

2. On the modal's name TextInput, keep `autoFocus` but also add `returnKeyType="done"` and `onSubmitEditing={saveEdit}` for quick save from keyboard.

   ```jsx
     size={16}
     color="#d1d5db"
     style={{ marginLeft: 8 }}
   />
   ```
   This goes AFTER the QuantityStepper (for unchecked) and after the quantity badge (for checked). It should be the last child of the Pressable, always rendered regardless of checked state. Use `#d1d5db` color (light gray) to be subtle but visible, matching the chevron-forward pattern used in settings screens.

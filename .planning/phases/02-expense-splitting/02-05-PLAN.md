**1. Fix get_household_balances() settlement sign inversion (supabase/migrations/00002_expenses.sql)**

In the `combined` CTE of `get_household_balances()`, swap the signs on the two settlement rows:

- Line 95 (currently `SELECT creditor AS other_user, -amount`): Change to `SELECT creditor AS other_user, amount` -- when I settle (pay them), it REDUCES what I owe, which means the balance from my perspective becomes MORE positive (less negative). So this should be +amount.
- Line 99 (currently `SELECT debtor AS other_user, amount`): Change to `SELECT debtor AS other_user, -amount` -- when they settle (pay me), it REDUCES what they owe, which means the balance from my perspective becomes LESS positive. So this should be -amount.

The corrected combined CTE settlement rows should read:
```sql
-- I settled (paid them), reduces what I owe
SELECT creditor AS other_user, amount
FROM settlement_credits WHERE debtor = auth.uid()
UNION ALL
-- They settled (paid me), reduces what they owe me
SELECT debtor AS other_user, -amount
FROM settlement_credits WHERE creditor = auth.uid()
```

**1. Pass description to settle screen from expenses tab (app/(app)/(tabs)/expenses.tsx)**

The settle screen is navigated to from two places in the expenses tab -- the "Settle Up" buttons in the balance dashboard (both "owed_to_you" and "you_owe" sections). These navigate with `router.push` passing `userId`, `amount`, and `direction` as query params.

Since the settle-up flow is balance-level (not tied to a single expense), the description should summarize recent activity. The most recent expense description between the two users is the best candidate for the Venmo note.

However, the settle screen is balance-level and the balance could come from multiple expenses. The user's request was specifically: "I'd rather it be the description such as 'Water Bill' and then with the date. So 'Water Bill - 03/11/26'".

Approach: In the expenses tab, when building `owedToYou` and `youOwe` entries, we already have the full expense history loaded (`groupedHistory`). For each balance entry, find the MOST RECENT expense that involves both the current user and the balance entry's user. Pass that expense's description and created_at date as additional params to the settle screen.

In `expenses.tsx`, add a helper function `getRecentExpenseForUser(userId: string)` that iterates through `groupedHistory` items and finds the first (most recent, since they're sorted desc) expense where `paid_by` matches either the current user or the balance user and the other is a split member. Since we don't have split data loaded, a simpler approach: find the most recent expense where `paid_by` is either the current user or the balance user.

```typescript
function getRecentExpenseForUser(userId: string): { description: string; date: string } | null {
  for (const group of groupedHistory) {
    for (const item of group.items) {
      if (item.type === 'expense') {
        if (item.data.paid_by === userId || item.data.paid_by === user?.id) {
          return {
            description: item.data.description,
            date: item.data.created_at,
          };
        }
      }
    }
  }
  return null;
}
```
